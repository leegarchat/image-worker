# image-worker

> Высокопроизводительная модульная user-space утилита на Rust для глубокой инспекции (`read`), модификации (`write`) и взаимной конвертации (`convert`) образов файловых систем Android (`ext4`, `EROFS`), а также контейнеров Android Sparse (`simg`).

Утилита полностью автономна: не требует прав суперпользователя (`root`), монтирования через ядро Linux (`mount` / `loop`-устройства), FUSE или внешних бинарников (`e2fsprogs`, `erofs-utils`, `simg2img`). Все низкоуровневые манипуляции с блоками и метаданными происходят строго в изолированном пространстве процесса.

---

## Ключевые возможности

* **100% Standalone User-Space**: Прямой парсинг, изменение и генерация структур файловых систем на чистом безопасном Rust.
* **Zero-Panic Policy**: В кодовой базе исключены `unwrap()`, `expect()` и `panic!` во всех рабочих путях. Все парсеры структур обёрнуты в модуль проверки границ `crate::core::buf` с возвратом `Result<_, Error>`.
* **Строгая экономия памяти ($O(1)$ RAM / Streaming)**: Чтение, запись и конвертация ведутся потоковыми квантами по 64 KiB для файловых систем и 256 KiB для Sparse. Пиковое потребление оперативной памяти (Peak RSS) не превышает 5–25 МБ даже на многогигабайтных системных образах. Многогигабайтные разделы никогда не оседают в RAM целиком.
* **Безупречный перенос SELinux (Zero-Loss)**:
  * **ext4**: Извлечение и сериализация меток `security.selinux` как из инлайн-области инода (`extra area`), так и из внешних блоков расширенных атрибутов (`i_file_acl`).
  * **EROFS**: Считывание инлайн- и shared-атрибутов; генерация при записи общей дедуплицированной таблицы `xattr_blkaddr` с безопасным пропуском диапазона суперблока при назначении NID.
  * **Сквозной Roundtrip**: Полная побайтовая сохранность контекстов безопасности при цепочке `ext4 -> EROFS -> ext4` без сбоев `e2fsck`.
* **Полноценное удаление (`--rm` / `-R`)**: Безопасное удаление файлов и поддеревьев с очисткой каталогов и физическим сжатием блочного пространства.
* **Реальное уменьшение ext4 (`--compact`)**: Расчёт геометрии от минимального числа групп блоков снизу вверх с предварительной оценкой дедупликации разделяемых блоков (`--shared-blocks`).
* **Многопоточный компрессор EROFS**: Встроенный упаковщик кластеров LZ4 и Deflate на базе `rayon`, автоматически предотвращающий раздувание несжимаемых данных.
* **EROFS Overlay Delta-Rebuild**: Мгновенная правка метаданных и дозапись файлов без декомпрессии существующих блоков (коэффициент роста 1.00x).

## Архитектура репозитория

```text
src/main.rs        Точка входа, диспетчер команд и автоопределение режима write/read
src/core/          Единое системное ядро I/O:
  buf.rs           Безопасные LE-ридеры границ (u16le, u32le, u64le, bytes)
  error.rs         Унифицированный перечень ошибок (thiserror)
  image.rs         Контейнеры Raw / Android Sparse, stdin-буфер, потоковый simg-энкодер
  util.rs          Парсер сигнатур типов (ELF, APK, DEX), форматирование прав, glob-маски
src/fs/            Файловые бэкенды (единый источник истины для чтения и записи):
  ext4/            Суперблок, иноды, дерево экстентов, директории, inline и block xattr
  erofs/           Суперблок, иноды, compact-кластеры, LZ4/Deflate/ZSTD, таблицы xattr
src/read/          Подпрограмма read (аудит, поиск, инспекция метаданных и streaming cat)
src/write/         Подпрограмма write и конвертеры:
  mod.rs           Дерево Node, очередь действий, overlay/append/legacy EROFS-ребилдеры
  ext4.rs          Copy-on-write сборщик ext4, планировщик групп, compact и shared-blocks
  convert.rs       Стриминговые конвертеры форматов без модификации дерева файлов
```

## Инженерные особенности и устранение типовых дефектов Android ФС

В утилите решён ряд специфических проблем и скрытых багов, свойственных альтернативным парсерам и скриптам перепаковки:

| Специфика / Дефект формата | Проблема типичных реализаций | Реализация в `image-worker` |
|---|---|---|
| **ext4 SELinux context** | Считывание со смещением на 4 байта раньше, из-за чего отрезался суффикс `:s0`. | Расчёт строго от `header + 4`, контекст считывается и сериализуется полностью. |
| **ext4 64bit detection** | Чтение флага 64bit из поля `ro_compat` (смещение 100). | Флаг читается строго из поля `incompat` (смещение 96) спецификации ext4. |
| **EROFS xattr listing** | Ограничение только инлайном, игнорирование shared xattr-таблиц. | Полный разбор inline и shared xattr-таблиц без потерь меток безопасности. |
| **EROFS Directory padding** | Нулевые байты заполнения (`\0`) попадали в имена, ломая glob-поиск. | Трейлинг-байты заполнителя безопасно обрезаются при парсинге каталогов. |
| **EROFS 64-bit UID/GID** | Extended-иноды считывали UID как u16 со сдвигом (мусор `65537000:0`). | UID/GID читаются и записываются как `u32` со смещений 24..32. |
| **ext4 Block Aliasing** | Репакеры ссылались на старые адреса блоков, приводя к порче данных. | Потоковое копирование полезной нагрузки только в свежевыделенные блоки. |
| **ext4 Sparse Output** | Запрос флага sparse для ext4 часто игнорировался. | Полноценный потоковый энкодер Android Sparse контейнеров для ext4. |
| **ext4 Shrink Lock** | Итератор групп брал `.max(groups)`, блокируя уменьшение размера. | Алгоритм fixed-point снизу от 1 группы: удаление файлов реально уменьшает raw. |

## Защитные лимиты целостности (Hard Caps)

Для предотвращения паник, зацикливаний и атак по исчерпанию памяти (OOM) при разборе битых образов действуют строгие лимиты:

* **Максимальный размер единичного файла**: 16 GiB.
* **Максимальный распакованный кластер (pcluster)**: 64 MiB (штатные кластеры $\le$ 512 KiB).
* **Максимальный размер inline-области xattr**: 1 MiB.
* **Максимальная глубина вложенности каталогов**: 512 уровней (защита от циклических путей).
* **Максимальная глубина дерева экстентов ext4**: 16 уровней.
* **Ограничение аллокатора дедупликации**: Хэш-сет дедупликации ограничен 2 000 000 записей (~16 МБ RAM), предотвращая переполнение памяти при оценке огромных массивов.

## Сборка и компиляция

**Системные требования**:
* Rust toolchain (MSRV 1.85+ или стабильный выпуск edition 2024).
* Сборщик Cargo.
* Для статических сборок: musl-тулчейны или `cross` (подсказки по установке — в `build.sh --help`).

```bash
# Клонирование репозитория
git clone https://github.com/leegarchat/image-worker.git
cd image-worker

# Быстрая локальная сборка (хостовый таргет, динамическая)
cargo build --release
# -> target/release/image-worker

# Статические мультиархитектурные сборки через build.sh (musl, stripped):
#   --cargo | --cross | --auto   метод сборки (auto = cross при наличии контейнеров, иначе cargo)
#   --arch all|x64|x86|arm64|arm32
./build.sh --cargo --arch x64      # x86_64-unknown-linux-musl
./build.sh --cross --arch arm64    # aarch64 через контейнеры
./build.sh --arch all              # x86_64, x86, aarch64, armv7

# Прогон комплексного набора модульных тестов
cargo test
```

Выходы сборки:

* `dist/` — статические бинарники `image-worker-linux-*` (x86_64, x86, arm64, arm32).
* `target/push/` — push-копии `{name}_{arch}` (`x64`, `x86`, `arm64`, `arm32`), обновляются под собранную архитектуру, например для устройств:
  `adb push target/push/image-worker_arm64 /data/local/` (`dist/` и `target/` в gitignore).

## Справочник по интерфейсу CLI

Утилита автоматически определяет требуемую подпрограмму: наличие флагов файловых модификаций переключает движок в режим `write`, в остальных случаях активируется инспектор `read`:

```text
image-worker read [ОПЦИИ] <образ|-> [внутренний_путь]
image-worker write <вход> <выход> ДЕЙСТВИЕ... [ОПЦИИ]
image-worker write <вход> <выход> --convert-to <erofs|ext4> [ОПЦИИ]
```

Символ `-` вместо пути используется для чтения из `stdin` или потокового вывода в `stdout`.

### 1. Подпрограмма `read` (Инспекция и аудит)

* `-i, --info` — Диагностика суперблока, контейнера и фичей файловой системы.
* `-l, --ls` — Листинг директории (по умолчанию корень `/`).
* `-f, --find [шаблон]` — Рекурсивный поиск по маске с поддержкой glob (`*`, `?`).
* `-c, --cat` — Потоковый вывод содержимого файла в `stdout` ($O(1)$ RAM).
* `-t, --type` — Отображение типа ноды (`file`, `directory`, `symlink`).
* `-F, --file-type` — Сниффинг содержимого по magic bytes (ELF, APK, DEX, XML, текст).
* `-o, --owner` — Отображение `UID:GID`.
* `-p, --permissions` — Права в символьном представлении (`rwxr-xr-x`).
* `-n, --numeric-permissions` — Права в восьмеричном формате (`0755`).
* `-s, --size` — Размер объекта в байтах.
* `-H, --human-size` — Размер в удобных единицах (`KiB`, `MiB`, `GiB`).
* `-Z, --context` — Вывод строки SELinux-контекста.
* `--stdin` — Чтение входного образа из стандартного потока ввода.

**Примеры применения:**
```bash
# Диагностика структуры и типа контейнера
image-worker read --info vendor.img

# Подробный листинг системного каталога с SELinux-метками
image-worker read -l -p -o -Z vendor.img /etc

# Рекурсивный поиск файлов конфигурации монтирования
image-worker read --find="*fstab*" -Z vendor.img /

# Извлечение файла build.prop напрямую в терминал
image-worker read --cat vendor.img /etc/build.prop > build.prop
```

---

### 2. Подпрограмма `write` (Модификация, удаление и репак)

**Действия над файлами:**
* `--add, -A <хост_путь> <путь_в_образе>` — Добавление или перезапись файла (`-` для чтения из stdin).
* `--cp, -C <исходный_путь> <целевой_путь>` — Копирование внутри образа с дедупликацией блоков.
* `--mv, -M <исходный_путь> <целевой_путь>` — Переименование/перемещение ноды с сохранением инода.
* `--rm <путь_в_образе>` — Удаление единичного файла или пустого каталога.
* `-R, -r <путь_в_образе>` — Рекурсивное удаление каталога со всем вложенным деревом.

**Модификаторы метаданных (передаются после действия `--add`/`--cp`/`--mv`):**
* `--mode <восьмеричный_режим>` — Задание прав (`0644`, `0755`).
* `--uid <UID>` / `--gid <GID>` — Задание числовых идентификаторов владельца.
* `--context <selinux_метка>` — Явный SELinux-контекст.

**Прямое изменение метаданных существующих файлов:**
* `--set-mode <путь> <режим>` — Смена битов разрешений.
* `--set-owner <путь> <uid:gid>` — Смена владельца ноды.
* `--set-context <путь> <контекст>` — Смена метки безопасности SELinux.

**Параметры геометрии и оптимизации размера:**
* `--compact` — Сжатие raw-образа ext4 до минимально возможного числа групп блоков (включается автоматически при вызове `--rm`).
* `--shared-blocks <y|n>` — Дедупликация одинаковых блоков в ext4 (нулевые блоки трансформируются в sparse-дыры).
* `--reserve-mb <размер>` — Гарантированный запас свободного пространства в ext4 (`64`, `128M`, `1G`).
* `--compress <lz4|deflate|none>` — Выбор алгоритма компрессии EROFS.
* `--sparse-output` — Генерация выходного файла в контейнере Android Sparse (`simg`).

**Примеры применения:**
```bash
# Замена системного файла с назначением правильного контекста SELinux
image-worker write vendor.img out.img \
    --add hosts /etc/hosts --mode 0644 --context u:object_r:vendor_configs_file:s0

# Изменение файла на лету через потоковый конвейер
cat new_fstab | image-worker write vendor.img out.img \
    --add - /etc/fstab.qcom --mode 0644

# Рекурсивное удаление каталога с физическим уменьшением raw-образа ext4
image-worker write vendor.img out.img -R /app/PrebuiltApp --compact

# Полная перепаковка EROFS с многопоточным сжатием Deflate
image-worker write vendor_erofs.img out_deflate.img \
    --rm /etc/unneeded.xml --compress deflate
```

### 3. Подпрограмма `convert` (Сквозная конвертация форматов)

```text
image-worker write <вход> <выход> --convert-to <erofs|ext4> [ОПЦИИ]
```

* `ext4 -> erofs` — Перекодирование файлового дерева в EROFS. По умолчанию активируется компрессия LZ4 (`--compress lz4`). Метки SELinux собираются в компактную разделяемую xattr-таблицу.
* `erofs -> ext4` — Чистая пересборка EROFS-образа в блочную структуру ext4. Все символические ссылки, типы узлов, права и контексты безопасности переносятся идентично байт-в-байт. Полученный образ проходит 5 проходов `e2fsck -fn`.
* `raw <-> sparse` (одинаковая ФС) — Потоковая трансформация контейнера без разбора и пересборки файлового дерева.

**Примеры применения:**
```bash
# Конвертация раздела ext4 в EROFS со сжатием LZ4
image-worker write vendor_ext4.img vendor_erofs.img --convert-to erofs

# Конвертация ext4 в ультракомпактный EROFS со сжатием Deflate
image-worker write vendor_ext4.img vendor_erofs.img --convert-to erofs --compress deflate

# Конвертация EROFS в ext4 с гарантированным запасом 128 МБ свободного места
image-worker write vendor_erofs.img vendor_ext4.img --convert-to ext4 --reserve-mb 128

# Разворачивание sparse-контейнера в блочный raw-образ
image-worker write vendor.sparse.img vendor.raw.img --convert-to erofs

# Упаковка raw-образа в Android Sparse контейнер
image-worker write vendor.raw.img vendor.sparse.img --convert-to ext4 --sparse-output
```

## Важные нюансы окружения: переполнение `TMPDIR`

В подавляющем большинстве дистрибутивов Linux (Ubuntu, Fedora, Arch, Debian) каталог `/tmp` по умолчанию монтируется как **виртуальный диск в оперативной памяти (`tmpfs`)** с лимитом в 50% от физического объёма RAM.

### Суть проблемы
При выполнении операций пересборки больших разделов (1.5–4.0 ГБ), упаковки через `stdin`/`stdout` (`-`) или создании Sparse-контейнеров утилита задействует временный seekable-файл (`spool_temp`). 
Если система оснащена 16 ГБ RAM, каталог `/tmp` вмещает не более 8 ГБ данных. Конвейерная обработка нескольких системных образов подряд моментально переполняет `tmpfs`. Ядро блокирует системный вызов `write()`, возвращая ошибку `ENOSPC (No space left on device)`, что может приводить к аварийной генерации пустых файлов.

### Решение
Утилита строго соблюдает стандарт POSIX: при формировании временных очередей приоритет отдаётся переменной окружения `TMPDIR`. Перед масштабными операциями перенаправляйте временный каталог на физический накопитель:

```bash
# Разовое выполнение команды с временным каталогом на NVMe/SSD:
TMPDIR=/mnt/nvme_disk/temp image-worker write vendor.img out.img --convert-to erofs

# Экспорт переменной на всю сессию терминала или внутри shell-скрипта:
export TMPDIR=~/build_workspace/tmp
```
