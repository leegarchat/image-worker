# image-worker-rework

Высокопроизводительная модульная user-space утилита на Rust для глубокой инспекции (read), модификации (write) и взаимной конвертации (convert) образов файловых систем Android (ext4, EROFS), а также контейнеров Android Sparse (simg).

Проект является единым преемником раздельных инструментов `image-inspect` (чтение) и `image-repack-rework` (запись). Утилита полностью автономна: не требует прав root, монтирования через ядро Linux (mount / loop-устройства), FUSE или сторонних бинарников (e2fsprogs, erofs-utils, simg2img). Все операции выполняются строго внутри процесса.

================================================================================
ОСНОВНЫЕ ВОЗМОЖНОСТИ И АРХИТЕКТУРА
================================================================================

1. 100% Standalone User-Space:
   - Полная независимость от root и внешних утилит хоста.
   - Прямой парсинг и генерация блочных структур файловых систем на чистом Rust.
   - Zero-Panic Policy: отсутствие unwrap/expect/panic в рабочем коде; безопасная валидация границ всех бинарных структур через модуль core::buf.

2. Память O(1) и потоковая обработка (Streaming):
   - Потоковое чтение и запись квантами по 64 KiB для ФС и 256 KiB для Sparse.
   - Пиковое потребление оперативной памяти (Peak RSS) держится в пределах 5–25 МБ даже при обработке многогигабайтных системных образов. Многогигабайтные разделы никогда не оседают в RAM целиком.

3. Полная поддержка безопасности SELinux (Zero-Loss):
   - ext4: извлечение и сериализация меток security.selinux как из инлайн-области инода (extra area), так и из внешних блоков расширенных атрибутов (i_file_acl).
   - EROFS: считывание инлайн и разделяемых (shared) xattr-таблиц; сборка выходных образов с генерацией дедуплицированной общей таблицы xattr_blkaddr и двухслотными 64-байтными NID.
   - Сквозной перенос контекстов при конвертации ext4 <-> EROFS с побайтовой идентичностью меток безопасности.

4. Модификация, сжатие и уменьшение размера (Shrink):
   - Поддержка удаления файлов и каталогов (--rm, -R).
   - ext4: режим компактного размещения (--compact) с расчетом минимально необходимого числа групп блоков снизу вверх и предварительной оценкой дедупликации (--shared-blocks).
   - EROFS: встроенный многопоточный компрессор (LZ4 / Deflate) через Rayon, сохраняющий потоковую запись и не раздувающий образ при несжимаемых данных.
   - EROFS Overlay: сверхбыстрое добавление и правка метаданных без распаковки существующих сжатых блоков (1.00x growth).

================================================================================
СТРУКТУРА ПРОЕКТА (LAYOUT)
================================================================================

src/main.rs        Точка входа: диспетчеризация команд и эвристика выбора режима.
src/core/          Единое низкоуровневое ядро:
  buf.rs           Безопасные ридеры с проверкой границ (u16le, u32le, u64le, bytes).
  error.rs         Унифицированный тип ошибок (thiserror).
  image.rs         Контейнеры Raw и Android Sparse, буферизация stdin, временные
                   файлы, потоковые кодировщики sparse (O(1) RAM, два прохода).
  util.rs          Определение типов файлов, форматирование прав, парсинг сигнатур
                   содержимого (ELF, APK, DEX, XML, zip), сопоставление glob-масок.
src/fs/            Файловые системы (единый источник истины для read и write):
  ext4/            Суперблок, иноды, дерево экстентов, директории, inline и block xattr.
  erofs/           Суперблок, иноды, plain/inline раскладки, директории, распаковка
                   и сжатие компактных кластеров (LZ4/Deflate/ZSTD), таблицы xattr.
src/read/          Подкоманда read: полная совместимость с image-inspect CLI.
src/write/         Подкоманда write и convert:
  mod.rs           Дерево Node, очередь действий (Action/Metadata), append-патчер,
                   overlay delta-rebuild, legacy rebuild, CLI.
  ext4.rs          Copy-on-write пересборка ext4, компактный режим, shared-blocks.
  convert.rs       Конвертеры форматов без модификации файлов (чистые перепаковщики).

================================================================================
ИСПРАВЛЕНИЯ И ОТЛИЧИЯ ОТ ПРАРОДИТЕЛЕЙ (IMAGE-INSPECT / REPACK)
================================================================================

В сравнении с оригинальными утилитами `image-inspect` и `image-repack-rework` устранены критические архитектурные дефекты:

1. Чтение ext4 SELinux:
   `image-inspect` считывал контекст со смещением на 4 байта раньше положенного, из-за чего строка теряла завершающий суффикс `:s0`. В текущей версии смещение выверено по e2fsprogs, контексты извлекаются полностью.
2. Флаг ext4 64bit:
   Определение флага 64bit перенесено в поле `incompat` (смещение 96). `image-inspect` ошибочно считывал его из `ro_compat` (смещение 100).
3. EROFS SELinux (-Z):
   Оригинальный ридер не поддерживал xattr и всегда выводил `context=-`. Теперь EROFS полноценно читает и инлайн-атрибуты, и общие таблицы (shared xattrs).
4. Завершающие нули в EROFS:
   Имена файлов в директориях EROFS очищаются от завершающего padding-мусора `\0` (например, `media_profiles_*.xml`), который ломал сопоставление масок в shell.
5. UID/GID в 64-битных инодах EROFS:
   В оригинальном репакере при `--set-owner` на расширенных (64-байтных) инодах записывался мусор вида `65537000:0`, так как поля UID/GID ошибочно трактовались как u16 со сдвигом на 32..40 байт. Исправлено: UID/GID читаются и пишутся строго как u32 по смещениям 24..32.
6. Устранение порчи файлов (Block Aliasing):
   Старый full rebuild при перепаковке ссылался на исходные блочные адреса нетронутых файлов. При записи новых данных блоки перезаписывались, что приводило к тихой порче содержимого. Теперь все данные файлов потоково распределяются строго в новые выделенные блоки.
7. Поддержка ext4 --sparse-output:
   В оригинальном `image-repack-rework` флаг `--sparse-output` для ext4 молча игнорировался и всегда писался raw-образ. В текущей версии флаг полностью поддержан.

================================================================================
ЖЁСТКИЕ ЛИМИТЫ БЕЗОПАСНОСТИ (HARD CAPS)
================================================================================

Для защиты от зависаний, переполнения стека и OOM-паник при обработке намеренно поврежденных или вредоносных образов в коде зафиксированы жесткие границы:
- Максимальный размер отдельного файла: 16 GiB.
- Максимальный размер декомпрессированного кластера EROFS (pcluster): 64 MiB.
- Максимальный размер области расширенных атрибутов (xattr area): 1 MiB.
- Максимальная глубина рекурсии каталогов: 512 уровней (защита от циклов).
- Максимальная глубина дерева экстентов ext4: 16 уровней.
- Потоковый ZSTD-декодер жестко ограничен чтением `output_size + 1` байт во избежание бесконечной генерации мусора.

ИСПОЛЬЗОВАНИЕ И СИНТАКСИС
================================================================================

Формат вызова:
  image-worker-rework read [ОПЦИИ] <образ|-> [внутренний_путь]
  image-worker-rework write <вход> <выход> ДЕЙСТВИЕ... [ОПЦИИ]
  image-worker-rework write <вход> <выход> --convert-to <erofs|ext4> [ОПЦИИ]

Если подкоманда не указана, наличие действий модификации автоматически выбирает `write`, в остальных случаях вызывается `read`. Знак `-` поддерживается для потоков stdin/stdout.

--------------------------------------------------------------------------------
1. РЕЖИМ ИНСПЕКЦИИ (READ)
--------------------------------------------------------------------------------

Параметры:
  -i, --info                 Диагностическая информация об образе и файловой системе.
  -l, --ls                   Список файлов в каталоге.
  -f, --find [шаблон]        Рекурсивный поиск файлов (поддерживает glob-маски * и ?).
  -c, --cat                  Потоковый вывод содержимого файла в stdout.
  -t, --type                 Отображать тип объекта (file, directory, symlink и т.д.).
  -F, --file-type            Определение сигнатуры содержимого (ELF, APK, DEX, XML, текст).
  -o, --owner                Отображать UID:GID.
  -p, --permissions          Отображать права доступа в символьном виде (rwxr-xr-x).
  -n, --numeric-permissions  Отображать права доступа в восьмеричном виде (0755).
  -s, --size                 Отображать размер в байтах.
  -H, --human-size           Размер в человекочитаемом формате (B, KiB, MiB, GiB).
  -Z, --context              Отображать SELinux-контекст файла.
  --stdin                    Чтение образа из стандартного потока ввода.

Примеры:
  image-worker-rework read --info vendor.img
  image-worker-rework read -l -p -o -Z vendor.img /etc
  image-worker-rework read --find="*fstab*" -Z vendor.img /
  image-worker-rework read --cat vendor.img /etc/build.prop > build.prop

--------------------------------------------------------------------------------
2. РЕЖИМ МОДИФИКАЦИИ И ПЕРЕСБОРКИ (WRITE)
--------------------------------------------------------------------------------

Действия над файлами:
  --add, -A <хост_файл> <путь_в_образе>
      Добавить или заменить файл. Источником может быть '-' для чтения из stdin.
      При замене старые права, владельцы и SELinux сохраняются, если не переопределены.

  --cp, -C <источник_в_образе> <назначение_в_образе>
      Скопировать файл внутри образа (несжатые данные дедуплицируются блоками).

  --mv, -M <источник_в_образе> <назначение_в_образе>
      Переместить или переименовать файл внутри образа.

  --rm <путь_в_образе>
      Удалить файл или пустой каталог.

  -R, -r <путь_в_образе>
      Рекурсивно удалить каталог со всем его содержимым.

Метаданные (применяются к предшествующему действию --add/--cp/--mv):
  --mode <режим>               Задать права доступа (например, 0644 или 0755).
  --uid <UID>                  Задать идентификатор пользователя.
  --gid <GID>                  Задать идентификатор группы.
  --context <строка_selinux>   Задать SELinux-контекст.

Точечное изменение метаданных существующих файлов:
  --set-mode <путь> <режим>    Изменить права (0755).
  --set-owner <путь> <uid:gid> Изменить числового владельца.
  --set-context <путь> <selinux> Изменить метку SELinux.

Опции упаковки:
  --compact                    Сжать raw-образ ext4 до минимально возможного числа
                               групп блоков (автоматически включается при --rm).
  --shared-blocks <y|n>        Включить/выключить дедупликацию идентичных блоков ext4.
  --reserve-mb <размер>        Зарезервировать свободное место в ext4 (64M, 1G).
  --compress <lz4|deflate|none> Выбор сжатия для EROFS (по умолчанию lz4).
  --sparse-output              Сформировать выходной файл как Android Sparse (simg).

Примеры:
  image-worker-rework write vendor.img out.img \
      --add README.md /etc/README.md --mode 0644 --context u:object_r:vendor_file:s0

  cat new_fstab | image-worker-rework write vendor.img out.img \
      --add - /etc/fstab.qcom --mode 0644

  image-worker-rework write vendor.img out.img -R /app/HugeApp --compact

  image-worker-rework write vendor_erofs.img out_erofs.img \
      --rm /etc/hosts --compress deflate

--------------------------------------------------------------------------------
3. РЕЖИМ КОНВЕРТАЦИИ (CONVERT)
--------------------------------------------------------------------------------

Формат:
  image-worker-rework write <вход> <выход> --convert-to <erofs|ext4> [ОПЦИИ]

ext4 -> erofs:
  Перекодировка дерева в EROFS со сжатием LZ4 или Deflate. SELinux-контексты
  упаковываются в разделяемую таблицу xattr.
erofs -> ext4:
  Чистая пересборка с сохранением всех атрибутов, симлинков и меток SELinux.
  Выходной ext4 проходит валидацию e2fsck без ошибок.
Та же ФС:
  Потоковая трансформация контейнера raw <-> Android sparse без пересборки ФС.

Примеры:
  image-worker-rework write vendor_ext4.img vendor_erofs.img --convert-to erofs
  image-worker-rework write vendor_ext4.img vendor_erofs.img --convert-to erofs --compress deflate
  image-worker-rework write vendor_erofs.img vendor_ext4.img --convert-to ext4 --reserve-mb 128
  image-worker-rework write vendor.sparse.img vendor.raw.img --convert-to erofs
  image-worker-rework write vendor.raw.img vendor.sparse.img --convert-to ext4 --sparse-output

================================================================================
ПОДВОДНЫЕ КАМНИ, СИСТЕМНЫЕ ОГРАНИЧЕНИЯ И TMPDIR
================================================================================

1. Критично: Лимиты TMPDIR и оперативной памяти (tmpfs):
   В современных дистрибутивах Linux каталог /tmp монтируется как tmpfs — то есть
   виртуальный диск в оперативной памяти (RAM), ограниченный 50% ее объема.
   При работе через stdin/stdout (-), пересборке ext4 и конвертации sparse создаются
   временные файлы (spool temp files).

   В ЧЕМ ОПАСНОСТЬ:
   При 16 ГБ RAM каталог /tmp вмещает не более 8 ГБ. При одновременной пересборке
   нескольких системных разделов по 2–4 ГБ память tmpfs мгновенно исчерпывается.
   ОС возвращает ошибку ENOSPC (No space left on device), порождая пустые файлы.

   КАК ИЗБЕЖАТЬ:
   Утилита image-worker-rework строго следует стандарту POSIX и при создании
   временных файлов в первую очередь проверяет переменную окружения TMPDIR.
   При работе с тяжелыми образами перенаправляйте временные файлы на физический диск:

   TMPDIR=/path/to/real/nvme/tmp ./image-worker-rework write ...
   # или для всей сессии терминала:
   export TMPDIR=~/my_project/tmp_build

2. Специфика удаления файлов (--rm / -R) в EROFS и ext4:
   - В EROFS при добавлении файлов работает инкрементальный оверлей (overlay): он
     дописывает данные в конец образа. Физически вырезать данные из середины сжатого
     архива EROFS невозможно. Поэтому действия --rm или явный флаг --compress
     форсируют полную пересборку (full rebuild), собирая чистый образ только из
     оставшихся файлов.
   - В ext4 размер раздела изначально фиксирован под физический раздел смартфона.
     Чтобы при удалении файлов раздел действительно уменьшился в мегабайтах (shrink),
     обязательно используйте флаг --compact (включается автоматически при --rm).

3. Поддержка сжатия EROFS (Cluster Compression):
   - Утилита формирует каноничные 4 KiB pcluster'ы (cluster_bits = 0), поддерживаемые
     всеми ядрами Android.
   - Если кластер данных не сжимается (уже сжатые JPEG, PNG, APK/ZIP), компрессор
     автоматически сохраняет его как plain cluster. Выходной образ EROFS никогда не
     станет больше исходного объема данных.

4. Ограничения ext4:
   - Поддерживаются 32-байтные дескрипторы групп (стандарт Android system/vendor).
   - Файлы обязаны использовать экстенты. Устаревшие прямые/косвенные блоки не
     поддерживаются.
   - Журнал (journal), 64-битные дескрипторы (64bit) и мета-контрольные суммы
     (metadata_csum) отклоняются при открытии ext4 для обеспечения строгой
     детерминированности ребилда в user-space.
